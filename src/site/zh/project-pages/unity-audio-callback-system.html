一套开源、线程安全的回调工作流，用于将 Unity 事件与音频中的精确时间点同步。

项目概述

Unity 内置音频系统能够稳定地播放音频，但若要让游戏逻辑、动画或视觉效果与音频中的精确时刻同步，往往需要为每个场景单独编写计时代码。我开发了这套系统，将 FMOD 和 Wwise 中常见的“标记 + 回调”工作流直接带入标准 Unity 项目。

设计师可以在 AudioEventAsset 中统一保存音频片段、播放参数和具名标记。AudioEventPlayer 负责播放音频，并在准确时刻触发每个标记对应的 UnityEvent；其他脚本也可以通过名称查找并订阅回调，因此该系统同时支持 Inspector 配置和运行时代码两种使用方式。

最终成果是一套轻量、开源的音频事件层，让时间信息可以复用、可视化，并始终贴近内容创作者的工作流程。

可复用的音频事件资产

基于 ScriptableObject 的 AudioEventAsset 是系统的数据核心。除了 AudioClip，它还保存音量、音高、循环、空间混合、Mixer 路由，以及循环时是否重复触发回调等参数。

每个标记由易读名称、时间戳和 UnityEvent 组成。计时数据因此不再依附于某个场景对象，同一份音频事件资产可以被不同播放器复用，并连接到不同的游戏反馈。

线程安全是系统设计的核心

播放器以 AudioSettings.dspTime 为基准调度播放，并在 OnAudioFilterRead 中检查已经过的 DSP 时间。由于该回调运行在 Unity 音频线程，系统绝不会在这里直接触发 UnityEvent 或访问游戏对象；到达时间点的标记只会通过非阻塞的 Enqueue 写入 ConcurrentQueue<EventMarker>。

主线程中的 Update 会持续调用 TryDequeue，并在成功取出标记后才触发对应的 UnityEvent。这条队列建立了清晰的线程边界：音频线程只负责精确的时间检测，主线程负责所有与 Unity 对象相关的副作用。两个线程不会同时遍历同一个共享列表，实时音频回调中也不需要持有锁。

对于循环音频，设计师可以选择在每次循环时重置标记索引并再次触发事件；非循环音频则会在播放结束后自然停止处理。

一条队列，两种清晰的线程职责

可视化波形编辑

我制作了自定义 Unity Editor 窗口，让设计师可以通过聆听和观察来调整时间，而不是反复手动输入秒数。编辑器会绘制当前音频的波形，支持带移动指针的音频预览，并提供缩放与水平滚动，以便进行精细定位。

用户可以直接点击波形添加标记、拖拽调整时间、从列表中选中、重命名、删除或输入精确数值。所选标记的 UnityEvent 也在同一窗口中编辑，让时间和行为在迭代过程中始终保持在一起。

Timeline 支持

自定义 AudioEventTrack、PlayableAsset 和 PlayableBehaviour 将同一事件系统扩展到 Unity Timeline。AudioEventPlayer 可以绑定到轨道，让播放与回调跟随 Timeline Graph，与动画、粒子、镜头及其他序列内容共同运行。

电影化内容与常规游戏逻辑因此可以复用同一套 AudioEventAsset 数据模型，无需维护第二套计时实现。
