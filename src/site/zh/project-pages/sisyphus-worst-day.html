概述

Sisyphus's Worst Day 是 USC 的一个高级游戏项目，开发周期为 10 个月。 这是一款第三人称解谜游戏，以幽默而现代的方式重新诠释了西西弗斯的神话。 玩家将扮演一名受众神指引的办公室职员，设法让西西弗斯困在永无止境的日常任务循环中。

作为首席技术声音设计师，我负责统筹音频制作流程，并确保所有声音元素都能通过 FMOD 与 Unity 有效整合进游戏。 我与另外四名声音设计师紧密合作，共同打造与游戏独特叙事和玩法机制相辅相成的沉浸式音频体验。

FMOD 与 Unity

音频实现主要通过 FMOD 创建交互式音频事件，再由 Unity 将这些事件整合进游戏。 我搭建了一套结构清晰的工作流程，让声音设计团队与开发团队能够高效协作，并确保所有音频资源都得到妥善整理与实现。

FMOD 工程通过 Perforce 进行管理与维护，为声音设计师之间的版本控制和协作提供支持。 我们在 FMOD 中统一整理并分类所有音频资源，从而保持稳定而高效的制作流程。

互动音乐与 3D 音频

游戏采用了一套互动音乐系统，音乐会根据当前游戏状态动态变化。

游戏分为布置阶段与运行阶段：玩家先设置谜题，随后观察西西弗斯尝试推动巨石。 音乐在两个阶段之间采用横向切换，通过 FMOD 的参数系统让两条完整混音的曲目自然交叉淡化。

所有画内音效都通过 FMOD 的 3D 音频功能置于三维空间中。 声音会随玩家在游戏世界中的位置与朝向产生变化，让整体体验更具沉浸感。

C# 开发

我们使用 C# 开发了一套自定义的全局音频管理器，负责将 FMOD 事件整合进 Unity。

该脚本统一管理音频播放、过渡与参数控制，确保声音能够动态响应玩家操作和游戏事件。 它将 FMOD 相关功能集中封装，并提供简洁的 API，让工程师无需了解底层 FMOD 实现，也能方便地触发音效和音乐事件。

配音系统

游戏中的多个场景都加入了配音。为了建立清晰的技术架构并贯彻数据驱动的设计方式， 我们在 Unity 中使用 ScriptableObject 管理配音台词及其对应音频文件，让内容可以在不修改代码的情况下轻松更新和调整。

ScriptableObject 会自动将每句台词与相应的音频文件关联，确保游戏系统始终能为对话取得正确的声音资源。

我们还为每个角色或场景创建了 VoiceOver ScriptableObject，用列表集中管理其所有台词。 这让配音内容的整理、实现与后续维护都更加清晰高效。

我们使用 C# 开发了一套自定义的全局音频管理器，用于处理 FMOD 事件与 Unity 之间的连接。

该系统负责音频播放、过渡和参数控制，使声音能够动态响应玩家操作与游戏事件。 集中封装的架构让工程师可以直接调用 API 触发音效和音乐，而不必理解底层的 FMOD 实现细节。

配音实现中的一个关键挑战，是角色在游戏过程中触发的情绪短句。

设计团队希望这些短句能够呈现不同情绪，并与对应的表情符号配合，为玩家创造更生动、更具表现力的反馈。

为了实现这一点，我们利用 FMOD 内置的参数与音频回调系统，动态查找正确的情绪标签，并将其传入线程安全队列。 负责播放行为的脚本随后会在 Update 线程中取出标签，再执行相应的表情符号逻辑。
