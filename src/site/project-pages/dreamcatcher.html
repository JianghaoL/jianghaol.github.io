Overview

Dreamcatcher is an ongoing game project where sound is both presentation and gameplay infrastructure. As Audio Lead, I own the audio production pipeline, Wwise implementation, realtime voice processing, sound-reactive mechanics, and the engineering work that connects microphone input to the game world.

During preproduction I synthesized 10 sound effects, organized the evolving asset workflow, and built Wwise structures for character, object, monster, UI, voice-chat, reverb, and spatial-audio content. The page focuses on the technical systems I designed and implemented in C++.

Realtime Proximity Voice

The local client captures 48 kHz mono PCM, accumulates it into RNNoise-compatible frames, and runs realtime denoising before encoding. A wet/dry control keeps the cleanup tunable, while a calibrated input gain is applied before the stream is metered and sent onward.

Compressed voice packets travel through an unreliable server RPC and multicast path, then remote clients decode them into a thread-safe queue consumed by a Wwise Audio Input source. Wwise handles spatial playback and distance behavior, keeping voice chat inside the same acoustic world as the rest of the game. I co-developed the networking portion with Junhang Ma.

Microphone Calibration

The calibration view reuses the live microphone path instead of simulating a separate meter. Wwise reports the input level through an RTPC, the UI converts it into a readable 0-100 range, and the player can tune denoise mix and microphone gain from -90 dB to +24 dB.

Calibration remains active while gameplay is paused, but packet transmission is explicitly suppressed. This keeps the level meter responsive without broadcasting setup audio to other players.

String Telephone

The string telephone turns network voice into a physical game mechanic. When a remote player enters one cup's pickup zone, the microphone component registers the opposite cup as a live sink. Decoded samples feed a dedicated Wwise Audio Input component at the far end, so speech emerges from the correct position in the world.

A configurable delay line holds the first packet until enough audio has accumulated. If packet loss or silence drains the queue, an atomic underrun flag re-arms the delay on the next packet instead of letting the intended transmission time collapse. The same delayed loudness history drives the cup glow and gameplay light radius, so the visible response arrives with the voice.

Wwise Production Architecture

The Wwise project separates voice chat, string telephone, player Foley, objects, monsters, UI, and reverbs into dedicated work units and busses. This keeps authoring responsibilities clear while allowing realtime voice to use the same attenuation, routing, RTPC, and spatial-audio systems as authored game content.

The current production set covers ball actions, material-based footsteps, character Foley, monster vocalizations, UI feedback, voice references, ambience, and room-specific acoustic treatment. The list continues to evolve with the game.

DreamIR - Work in Progress

I am developing DreamIR, a custom Wwise convolution-reverb effect. The current C++ implementation validates and loads impulse-response media, allocates one FIR convolver per channel, and processes audio in place inside the Wwise sound engine.

In parallel, I am researching a geometry-fit workflow that generates a custom impulse response for each room. Both the plug-in and per-room IR generation pipeline remain in active development.
