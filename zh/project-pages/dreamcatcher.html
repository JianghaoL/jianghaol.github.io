项目概述

Dreamcatcher 是一个仍在推进中的游戏项目，声音既承担表现，也构成玩法基础设施。作为音频负责人， 我负责音频制作流程、Wwise 实现、实时语音处理、声音驱动机制，以及把麦克风输入连接到游戏世界的工程工作。

在前期制作中，我合成了 10 个音效，组织持续更新的资源流程，并搭建了覆盖角色、物件、怪物、UI、 语音聊天、混响与空间音频内容的 Wwise 结构。本页重点展示我用 C++ 设计和实现的技术系统。 当前制作清单已记录 25 个具名音效条目。

实时近距离语音

本地客户端以 48 kHz 单声道采集 PCM，将数据累积为 RNNoise 所需的帧并实时降噪，然后再编码。 干湿比让降噪强度可调，校准后的输入增益则在电平检测与发送之前应用到信号上。

压缩语音包通过 Unreliable Server RPC 与 Multicast 链路传输，远端客户端解码后写入线程安全队列， 再由 Wwise Audio Input 消费。Wwise 负责空间定位与距离衰减，使语音聊天和游戏中的其他声音处于同一个声学世界。 网络部分由我与 Junhang Ma 共同开发。

麦克风校准

校准界面直接复用实时麦克风链路，而不是使用独立的模拟电平表。Wwise 通过 RTPC 返回输入电平， UI 将其映射到清晰的 0-100 范围，玩家可调整降噪干湿比与 -90 dB 至 +24 dB 的麦克风增益。

游戏暂停时校准仍会继续运行，但语音包发送会被明确禁止。这样电平表可以持续响应，同时不会把设置过程中的声音广播给其他玩家。

游戏内校准

工程构建把麦克风增益、降噪干湿比与校准直接放进暂停菜单。游戏暂停时电平表仍保持实时响应， 因此整条采集与处理链路可以被直接观察和测试，同时不会发送设置过程中的语音。

拉线电话

拉线电话把网络语音变成实体玩法机制。远端玩家进入一只纸杯的拾取区域后，麦克风组件会把另一端纸杯注册为实时接收端。 解码后的样本进入远端专用的 Wwise Audio Input 组件，因此语音会从游戏世界中的正确位置传出。

可配置的延迟线会先缓存首个语音包，直到积累足够音频。若丢包或静音使队列耗尽，原子化 underrun 标记会在下一个包到达时重新建立延迟， 防止设计好的传输时间逐渐归零。同一份延迟后的响度历史还会驱动纸杯光效与玩法光照半径，让可见反馈与语音同时抵达。

Wwise 制作架构

Wwise 项目把语音聊天、拉线电话、玩家拟音、物件、怪物、UI 与混响拆分到独立的 Work Unit 和总线中。 这种结构明确了制作职责，同时让实时语音与预制游戏音频共享衰减、路由、RTPC 与空间音频系统。

当前制作内容覆盖球体动作、材质脚步、角色拟音、怪物声音、UI 反馈、语音参考、环境声与房间声学处理； 资源清单会随着游戏开发持续更新。

DreamIR - 开发中

我正在开发 DreamIR，一款自定义 Wwise 卷积混响效果器。当前 C++ 实现可以验证并载入冲激响应媒体， 为每个声道分配独立 FIR 卷积器，并在 Wwise 声音引擎中原地处理音频。

同时，我正在研究基于房间几何匹配的工作流，为每个空间生成自定义冲激响应。插件与逐房间 IR 生成流程目前都仍在开发中。
